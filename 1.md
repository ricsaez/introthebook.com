To describe our language, we need to refer to things without choosing particular ones. We use **placeholders** for this.

For example, consider arithmetic. We can use `a` and `b` as placeholders for numbers:

    a + b

Replacing `a` with `2` and `b` with `3` gives:

    2 + 3

We can now begin describing our own language.

When we express something, we call what we express an **expression**.

To refer to an expression without choosing a particular one, we use the placeholder:

    e

We begin with **values**: expressions that are already finished. We use `v` as a placeholder for one.

Values belong to **types**. For our first types, we list the possible values. Using `T` for a type and `c`, `c'`, … for the names of its values, we write:

    T = c | c' | …

The `|` separates the possibilities. For example:

    Bool = false | true

This introduces a type, `Bool`, with two values: `false` and `true`. Each is also an expression. These are its only values: nothing else is a `Bool`.

To say that an expression `e` has type `T`, we write:

    e : T

For example:

    true : Bool

We can give an expression a name, so we can refer to it without repeating it. Using `x` as a placeholder for a name, we write:

    x = e

For example:

    answer = true

We can now use `answer` to refer to `true`.

A **function** gives an expression for each possible input. We describe it through **cases**. Each case says which expression to use for a particular input value:

    (v) ↦ e

This reads “given `v`, use `e`.”

Using `f` as a placeholder for the function’s name, we separate its cases with `|`:

    f = (v) ↦ e | …

For example:

    not = (true) ↦ false | (false) ↦ true

Given `true`, this function gives `false`; given `false`, it gives `true`.

Every possible input must match exactly one case. Since `Bool` has only two values, these two cases cover every input, and the function always has exactly one expression to give.

Giving a function an input is a **call**. We write the input in parentheses after the function’s name:

    f(v)

The call becomes the expression given by its matching case. We call this a **step**, and write it using `>>`:

    f(v) >> e

`>>` only shows a step; it is not part of the language.

For example:

    not(true) >> false

Both sides are expressions, and they mean the same thing: `false` is what `not(true)` means, said directly. The call reaches the value `false` in one step. A value takes no steps: it is already finished.

A function’s type describes its inputs and outputs. Using `A` for the input type and `B` for the output type, we write:

    f : A → B

For example:

    not : Bool → Bool

This says that `not` takes a `Bool` and gives back a `Bool`.

A case can give its input a name. We call this name a **variable**, and write:

    (x) ↦ e

This case accepts any value of the input type. Within `e`, `x` refers to that input. When we use the case, we replace `x` in `e` with the supplied value.

For example:

    identity : Bool → Bool
    identity = (b) ↦ b

This function gives back the value it receives:

    identity(true) >> true
    identity(false) >> false

A function can take several inputs. We separate them with commas:

    f(v, v')

A case can give each input a name:

    (x, y) ↦ e

When we use the case, we replace each variable in `e` with its corresponding input.

Using `A` and `B` for the input types and `C` for the output type, we write:

    f : (A, B) → C

For example:

    first : (Bool, Bool) → Bool
    first = (a, b) ↦ a

This function gives back its first input:

    first(true, false) >> true
    first(false, true) >> false

A function’s input can be an expression of the required type:

    f(e)

If `e` takes a step to another expression, `e'`, the whole call changes with it:

    f(e) >> f(e')

We use the function’s matching case once its inputs are values. Calls inside those inputs therefore go first.

When several inputs can take steps, we take them from left to right. Any other choice would reach the same value.

Following one step after another may lead to a value:

    e >> e' >> … >> v

For example:

    not(not(true)) >> not(false) >> true

The inner call becomes `false`. The outer call then becomes `true`.

A value can contain other values. We describe how to build it with a **constructor**. Using `c` for the constructor’s name and `A` and `B` for the types of its contents, we can define:

    T = c(A, B)

Given values `v : A` and `v' : B`, we can build:

    c(v, v') : T

Here `c(v, v')` is already a value, while a function call takes a step. The constructor keeps its contents together. The values we listed earlier, like `true` and `false`, are constructors with no contents.

For example:

    BoolPair = pair(Bool, Bool)

    pair(true, false) : BoolPair

Like a function’s inputs, a constructor’s contents can be any expressions of the right types. If `e` takes a step to `e'`, the expression containing it takes the same step:

    c(e, v) >> c(e', v)

The same holds for each of its contents. Once all of them are values, the whole expression is a value.

For example:

    pair(not(true), true) >> pair(false, true)

A case can give names to the values inside:

    (c(x, y)) ↦ e

When this case matches `c(v, v')`, we replace `x` with `v` and `y` with `v'` in `e`.

For example:

    left : BoolPair → Bool
    left = (pair(a, b)) ↦ a

    left(pair(true, false)) >> true

A constructor can hold a value of the type we are defining. Using `c` for a constructor with no contents and `c'` for one that holds another value, we write:

    T = c | c'(T)

Starting with `c`, we can build:

    c
    c'(c)
    c'(c'(c))
    …

Each is a value of type `T`.

For example, we can define the natural numbers:

    Nat = zero | succ(Nat)

`zero` represents zero. `succ` represents one more than the number it contains:

    zero
    succ(zero)
    succ(succ(zero))
    …

These represent zero, one, two, and so on. The same two constructors let us keep building larger numbers.

A function can call itself. We call this **recursion**.

For values built with `c` and `c'`, a case can use the same function on the value inside. Using `g` as a placeholder for another function, one possible form is:

    f = (c) ↦ e | (c'(x)) ↦ g(f(x))

Here, `f` is called on `x`, one layer inside the original value. When we reach `c`, the first case applies.

For example:

    even : Nat → Bool
    even = (zero) ↦ true | (succ(n)) ↦ not(even(n))

Zero is even. Each additional `succ` switches between even and odd, so we use `not` to switch the answer.

    even(succ(zero))
    >> not(even(zero))
    >> not(true)
    >> false

A name can be used anywhere, even before its own definition. So functions can also call each other. We could write `even` together with `odd`:

    even : Nat → Bool
    even = (zero) ↦ true | (succ(n)) ↦ odd(n)

    odd : Nat → Bool
    odd = (zero) ↦ false | (succ(n)) ↦ even(n)

    even(succ(zero))
    >> odd(zero)
    >> false

A function can also call itself with the same input:

    f = (x) ↦ f(x)

Each step then repeats the call:

    f(v) >> f(v) >> …

For example:

    loop : Bool → Bool
    loop = (b) ↦ loop(b)

    loop(true) >> loop(true) >> …

The steps continue forever without reaching a value. The expression has type `Bool`, but having a type does not guarantee that we will reach a value.

A call can use its matching case only after its inputs reach values:

    f(e, e') >> … >> f(v, v')

If an input takes steps forever, we never reach the point where we can use the case.

For example:

    first(true, loop(false))
    >> first(true, loop(false))
    >> …

Although `first` gives back its first input, our rule requires both inputs to become values. The second never does.

If we allowed the outer call to use its case immediately, this expression would become `true`. That would be a different rule for calls.

So the order of steps can never change which value we reach, but it can determine whether we reach one at all.

Only the matching case is ever used. So to keep an expression from taking steps, we put it inside a case:

    safe : Bool → Bool
    safe = (true) ↦ true | (false) ↦ loop(false)

    safe(true) >> true

`loop(false)` is never reached. This is also why recursion can stop: in `even`, the call inside the `succ` case is only reached when that case matches.

A function is also a value: it takes no steps until it is called. So a function can be the input of another function. The input’s type is then a function type, and the case can call it like any other function:

    f : (A → B, A) → B
    f = (g, x) ↦ g(x)

For example:

    twice : (Bool → Bool, Bool) → Bool
    twice = (g, b) ↦ g(g(b))

    twice(not, true)
    >> not(not(true))
    >> not(false)
    >> true

We write `twice` once, and give it whichever function we need: `twice(identity, true)` uses the same cases.

A function can also be written without a name, anywhere an expression can go. In particular, a function can give back a function. Its output type is then a function type:

    f : A → (B → C)
    f = (x) ↦ ((y) ↦ e)

For example:

    constant : Bool → (Bool → Bool)
    constant = (a) ↦ ((b) ↦ a)

Given `true`, `constant` gives back a new function:

    constant(true) >> (b) ↦ true

This function did not exist before the call: replacing `a` with `true` made it. It gives back `true`, whatever it is given. We can call it directly:

    constant(true)(false)
    >> ((b) ↦ true)(false)
    >> true

As with inputs, the function being called takes its steps first.

So far, a constructor’s contents have fixed types. `BoolPair` holds two `Bool`s, so a pair of numbers would need a new type, and `left` would have to be written again for it.

Instead, a type can take a type as an input. Using `A` for the type given, we write the type as `T(A)`, and its constructors can contain `A`s:

    T(A) = c(A) | …

For example:

    Pair(A) = pair(A, A)
    List(A) = empty | cons(A, List(A))

`Pair(Bool)` is a pair of `Bool`s, and `Pair(Nat)` a pair of numbers. A `List(A)` is either empty, or an `A` in front of another list of `A`s:

    cons(true, cons(false, empty)) : List(Bool)

A function’s type can use `A` too. Here `A` is not an input: like a variable, it stands for whichever type the input holds. So we write the function once, for every type:

    left : Pair(A) → A
    left = (pair(a, b)) ↦ a

    length : List(A) → Nat
    length = (empty) ↦ zero | (cons(x, rest)) ↦ succ(length(rest))

For example:

    length(cons(true, cons(false, empty)))
    >> succ(length(cons(false, empty)))
    >> succ(succ(length(empty)))
    >> succ(succ(zero))

The same `length` counts a list of numbers.

We can now put the whole language together.

Everything we can write in it takes one of these forms. Each `e` can be filled with any expression of the right type:

    e = x                   a name or a variable
      | c                   a constructor with no contents
      | c(e, …)             a constructor with its contents
      | e(e, …)             a call
      | (p, …) ↦ e | …      a function, as a list of cases

A name stands for the expression it names, and can be used anywhere, even before or inside its own definition.

Using `p` for a pattern, a case matches:

    p = x | c | c(p, …)

The values are the finished expressions:

    v = c | c(v, …) | (p, …) ↦ e | …

Types take these forms, where `T` is the name of a type or a variable for one:

    A = T | T(A, …) | (A, …) → A

We define names and types like this:

    x : A
    x = e
    T = c | c(A, …) | …
    T(A, …) = c | c(A, …) | …

A call takes a step once the function and its inputs are values. It becomes the expression of the case the inputs match, with each variable replaced:

    ((p, …) ↦ e | …)(v, …) >> e

Every other step happens inside a call or a constructor. If `e >> e'`, the expression containing it takes the same step:

    e(…) >> e'(…)
    v(…, e, …) >> v(…, e', …)
    c(…, e, …) >> c(…, e', …)

The function being called goes first, then the inputs or contents, from left to right.

Two rules complete the language: every expression must have the right type, and every input must match exactly one case.

This is the whole language. It can express anything that can be computed.
