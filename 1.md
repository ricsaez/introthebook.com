To describe our language, we need to refer to things without choosing particular ones. We use **placeholders** for this.

For example, consider arithmetic. We can use `a` and `b` as placeholders for numbers:

    a + b

Replacing `a` with `2` and `b` with `3` gives:

    2 + 3

We can now begin describing our own language.

When we express something, we call what we express an **expression**.

To refer to an expression without choosing a particular one, we use the placeholder:

    e

We begin with **values**. A value is an expression, and we use `v` as a placeholder for one.

Values belong to **types**. For our first types, we list the possible values. Using `T` for a type and `v`, `v'`, … for its values, we write:

    T = v | v' | …

The `|` separates the possibilities. For example:

    Bool = false | true

This introduces a type, `Bool`, with two values: `false` and `true`. Each is also an expression.

To say that an expression `e` has type `T`, we write:

    e : T

For example:

    true : Bool

We can give an expression a name, so we can refer to it without repeating it. Using `x` as a placeholder for a name, we write:

    x = e

For example:

    answer = true

We can now use `answer` to refer to `true`.

A **function** gives an expression for each possible input. We describe it through **cases**. Each case says which expression to use for a particular input value:

    (v) ↦ e

This reads “given `v`, use `e`.”

Using `f` as a placeholder for the function’s name, we separate its cases with `|`:

    f = (v) ↦ e | …

For example:

    not = (true) ↦ false | (false) ↦ true

Given `true`, this function gives `false`; given `false`, it gives `true`.

Giving a function an input is a **call**. We write the input in parentheses after the function’s name:

    f(v)

The call becomes the expression given by its matching case. We call this a **step**, and write it using `>>`:

    f(v) >> e

For example:

    not(true) >> false

Both sides are expressions. The call `not(true)` reaches the value `false` in one step.

A function’s type describes its inputs and outputs. Using `T` for the input type and `T'` for the output type, we write:

    f : T → T'

For example:

    not : Bool → Bool

This says that `not` takes a `Bool` and gives back a `Bool`.

A case can give its input a name. We call this name a **variable**, and write:

    (x) ↦ e

This case accepts any value of the input type. Within `e`, `x` refers to that input. When we use the case, we replace `x` in `e` with the supplied value.

For example:

    identity : Bool → Bool
    identity = (b) ↦ b

This function gives back the value it receives:

    identity(true) >> true
    identity(false) >> false

A function can take several inputs. We separate them with commas:

    f(v, v')

A case can give each input a name:

    (x, y) ↦ e

When we use the case, we replace each variable in `e` with its corresponding input.

Using `A` and `B` for the input types and `C` for the output type, we write:

    f : (A, B) → C

For example:

    first : (Bool, Bool) → Bool
    first = (a, b) ↦ a

This function gives back its first input:

    first(true, false) >> true
    first(false, true) >> false

A function’s input can be an expression of the required type:

    f(e)

If `e` takes a step to another expression, `e'`, the whole call changes with it:

    f(e) >> f(e')

We use the function’s matching case once its inputs are values. Calls inside those inputs therefore go first.

Following one step after another may lead to a value:

    e >> e' >> … >> v

For example:

    not(not(true)) >> not(false) >> true

The inner call becomes `false`. The outer call then becomes `true`.

A value can contain other values. We describe how to build it with a **constructor**. Using `c` for the constructor’s name and `A` and `B` for the types of its contents, we can define:

    T = c(A, B)

Given values `v : A` and `v' : B`, we can build:

    c(v, v') : T

Here `c(v, v')` is already a value, while a function call takes a step. The constructor keeps its contents together.

For example:

    BoolPair = pair(Bool, Bool)

    pair(true, false) : BoolPair

A case can give names to the values inside:

    (c(x, y)) ↦ e

When this case matches `c(v, v')`, we replace `x` with `v` and `y` with `v'` in `e`.

For example:

    left : BoolPair → Bool
    left = (pair(a, b)) ↦ a

    left(pair(true, false)) >> true

A constructor can hold a value of the type we are defining. Using `c` for a constructor with no contents and `c'` for one that holds another value, we write:

    T = c | c'(T)

Starting with `c`, we can build:

    c
    c'(c)
    c'(c'(c))
    …

Each is a value of type `T`.

For example, we can define the natural numbers:

    Nat = zero | succ(Nat)

`zero` represents zero. `succ` represents one more than the number it contains:

    zero
    succ(zero)
    succ(succ(zero))
    …

These represent zero, one, two, and so on. The same two constructors let us keep building larger numbers.

A function can call itself. We call this **recursion**.

For values built with `c` and `c'`, a case can use the same function on the value inside. Using `g` as a placeholder for another function, one possible form is:

    f = (c) ↦ e | (c'(x)) ↦ g(f(x))

Here, `f` is called on `x`, one layer inside the original value. When we reach `c`, the first case applies.

For example:

    even : Nat → Bool
    even = (zero) ↦ true | (succ(n)) ↦ not(even(n))

Zero is even. Each additional `succ` switches between even and odd, so we use `not` to switch the answer.

    even(succ(zero))
    >> not(even(zero))
    >> not(true)
    >> false

A function can also call itself with the same input:

    f = (x) ↦ f(x)

Each step then repeats the call:

    f(v) >> f(v) >> …

For example:

    loop : Bool → Bool
    loop = (b) ↦ loop(b)

    loop(true) >> loop(true) >> …

The steps continue forever without reaching a value. The expression has type `Bool`, but having a type does not guarantee that we will reach a value.

A call can use its matching case only after its inputs reach values:

    f(e, e') >> … >> f(v, v')

If an input takes steps forever, we never reach the point where we can use the case.

For example:

    first(true, loop(false))
    >> first(true, loop(false))
    >> …

Although `first` gives back its first input, our rule requires both inputs to become values. The second never does.

If we allowed the outer call to use its case immediately, this expression would become `true`. That would be a different rule for calls.

The choice of order can therefore determine whether an expression reaches a value at all.
